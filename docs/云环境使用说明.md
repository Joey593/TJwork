# TJwork 云环境与 GitHub 使用说明

## 当前会话

已将 `https://github.com/Joey593/TJwork` 克隆到 `/workspace/TJwork`，平台源码位于仓库根目录。

后续本会话中的平台文件创建与修改以该目录为准。旧路径 `/workspace/work/aurora-test` 已改为指向仓库的兼容符号链接，不是另一份工程。原有本地依赖与运行数据已一起迁入，保持为 Git 忽略文件。

可从仓库 README 查看启动步骤，从 `docs/验收报告.md` 查看已执行与未验证的项目。GitHub 的 Code → Download ZIP 可下载仓库源码；也可以使用：

```bash
git clone https://github.com/Joey593/TJwork.git
cd TJwork
```

Windows 使用 `start.ps1`，Linux/macOS 使用 `bash start.sh`。数据库数据、密钥、虚拟环境和 node_modules 不会随 GitHub 源码下载，应按 README 初始化。

## 以后新会话

仓库克隆和推送不会自动改变 Codex 的默认云环境。新会话请在环境/仓库选择处选中已配置的 TJwork，并确认工作目录中存在本仓库。

当前会话没有提供修改或发布可复用云环境配置的工具，因此本次只完成当前会话的仓库接入与工程迁移，没有将所有新会话的默认环境设置改写为 TJwork。

仓库根目录的 `AGENTS.md` 保存项目开发约定；后续以该仓库启动的会话可以读取并遵循。

## 同步与凭据

源文件修改发生在本地 checkout；提交并推送后才会显示在 GitHub。检查方式：

```bash
git status
git remote -v
git log -1 --oneline
```

真实 `.env`、数据库、JWT 密钥和本地依赖不纳入提交。访问令牌使用已连接的 GitHub 或环境配置，不写入仓库。
