# 可复现实验方案与指标口径

## 研究问题与对照

RQ1：规则约束是否改善 LLM 候选的结构和业务有效性？设置人工/规则基线、直接 LLM、规则约束 + LLM。每组采用相同需求、需求点、目标数量、页面契约与模型（两组 LLM），控制 temperature=0，并独立建需求记录，避免库内去重对不同组产生不对称影响。

两组 LLM 都执行相同后置 Schema 校验和人工审核门禁。直接组采用基础结构提示；约束组额外要求正常/异常/边界覆盖、可验证断言、禁止重复和语义化 Locator。实验应区分“原始模型输出质量”和“平台后处理入库质量”。

RQ2：语义化 Locator 对结构变更的适应性如何？对比 CSS、XPath 和 role/label/test-id，在 20 次重复中按固定规律修改按钮 class/id。每个方法相同变更安排。该实验测量人为结构变化的影响，不是自然偶发失败率。

RQ3：规则 + LLM 能否改善失败分类与摘要？使用独立人工标注的错误堆栈集，比较规则、直接 LLM、规则 + LLM，记录分类准确率、Macro-F1、调用耗时和逐条候选原因。默认 8 条 fixture 仅验证计算流程；论文实证应扩充真实失败样本并由两人或复核流程标注。

## 指标

| 指标 | 分子/分母与数据来源 |
| --- | --- |
| 需求点覆盖率 | 去重后的已关联需求点 / 需求点总数；生成实验可另算候选覆盖，平台概览统计已审核覆盖 |
| 结构有效率 | 原始候选中通过 Pydantic 的条数 / 原始生成条数；应报告去重前与去重后口径 |
| 可执行率 | 在正确版本被测系统完成预期操作与断言的用例数 / 结构有效条数；执行了错误脚本而返回失败不算可执行成功 |
| 重复率 | 按固定脚本+需求点哈希判定的重复条数 / 原始生成条数；语义重复可另做人工标注 |
| 预置缺陷检出率 | 唯一检出的预置缺陷数 / 预置缺陷总数；同一缺陷的多个失败不重复计数 |
| 人工修订时间 | 开始检查候选到批准可执行版本的实际人工计时，排除等待 API 的时间 |
| 生成耗时 | 服务端从组装输入到接收和校验完成的 monotonic 时间；与浏览器执行分开 |
| 自然偶发失败率 | 固定正确业务实现、固定同一用例重复运行时的非业务性失败数 / 运行次数 |
| 分类准确率 | 与人工标签相同的预测数 / 全部样本数；调用错误记错误 |
| Macro-F1 | 对 assertion/locator/timeout/infrastructure 四类分别计算 F1，再算平均 |

当分母为零时显示“—/null”，不显示无意义的 100%。生成记录的 valid_count 为校验通过且尚未去重的数量，processed_count 为实际处理的数量，accepted_count 为去组内重后的合法候选数，raw_count 为顶层候选总数，errors、duplicates 和 cross_duplicates 分开保存。新记录使用 valid_count / raw_count 计算完整处理时的结构有效率；旧记录若没有 valid_count，应从原始响应逐条验证。超过20条的未处理输出要单独报告，不能将 accepted_count 直接当作去重前有效数。

## 实验步骤

1. 固定依赖版本、模型名、Prompt 版本、被测应用与输入数据，记录平台配置和运行环境。
2. 执行 `collect.py --suite prepare`，检查 20 条数据驱动基线与 4 条缺陷用例，人工批准。
3. 执行 `collect.py --suite acceptance`，保存 20 条批量、20 次重复、四类缺陷与证据可用性的原始记录。
4. 执行 `collect.py --suite generation`。无密钥时只运行规则组，其他组明确标记 not_run。
5. 对各组候选开展人工审核，记录开始/结束计时、修订内容与版本。
6. 在正确版本应用验证可执行性，再在四种缺陷版本运行，按唯一缺陷统计检出。
7. 在「对比实验」录入观察值和生成/运行 ID，导出 CSV，保留每次试验，建议多轮独立重复，不只取最好一次。
8. 执行 `locator_stability.py`，保留每次选择器、变更标记、结果、耗时、错误与汇总。
9. 为失败分类实验准备独立数据集，运行 `failure_analysis.py --dataset your-dataset.json`，逐条复查预测，保存完整模型响应与数据出处。

## 有效性限制

本次交付使用合成演示应用和 4 个明确缺陷；结果不能外推到任意生产 Web 系统。20 次稳定性重复仅是任务书的最低验收样本。0/20 次失败不代表真实长期失败概率为零；例如粗略 rule-of-three 上界约 15%，因此应区分观测值与总体可靠性推断。

默认失败分类集较小，使用可直接由关键词识别的人工样例，得到高准确率仅说明流程可运行。无真实模型调用时，不报告直接 LLM 或规则 + LLM 的分类或生成效果。人工修订时间不由模型耗时替代。
